以下为先前实现记录；其中“不调用外部打法接口”已由上述文本分析流程更新，图片本身仍仅供本地识别。

图片页面 `/monitor` 先调用 `/api/picture/recognize` 识别英雄，再用 `/api/picture/personal-plan` 根据用户选择的英雄和分路生成个人方案，不再调用外部看图打法接口。旧建议接口保留，但不参与该页面的当前流程。

1. 从用户提交的当前图片读取 OCR，寻找两排各五个加载百分比及中间 VS。
2. 用名字文字确定每排名称区域，按本图测得的卡片间距裁剪十个槽位，不写死截图坐标或样本阵容。
3. 将名字放大并编号为 1–10，交给本地 Qwen 只读文字；OCR 可直接读到的英雄名用于核对。
4. 输出名称、槽位、裁剪位置和识别来源。冲突、重复、不可读的位置保留待确认，不移动后续位置，不凭阵容补齐。

`complete` 表示十个槽位都有通过名称约束的结果，并不代表校准后的百分之百准确率。使用的是仓库技能资料中的英雄名称集合；新增英雄需要同步资料。只缓存完整识别，失败可以直接重试。按图片内容缓存，不依赖查看阵营或分路。

目前支持加载百分比和英雄名字都可定位的双排 5v5 布局。低清、遮挡、单卡片、隐藏英雄名、其他布局会明确返回待确认。没有引入皮肤头像识别，不能宣称覆盖所有英雄的所有皮肤与截图。

安装依赖：`pip install -r requirements.txt`。新增依赖 rapidocr-onnxruntime，使用本地 OCR；Qwen 由 Ollama 提供。

验证：`python -m unittest discover -s tests -p test_hero_recognition.py -v`。真实图片结果存于 `work/hero-names-real.json`，为本地实际推理输出，无模拟返回。

个人方案绑定服务端识别记录、当前会话和图片修订号；客户端不能提交另一组阵容替换它。换图、跨会话、过期、不完整识别或选择敌方英雄均拒绝。切换分路仅重新生成本地个人方案，不重复视觉识别。方案包含英雄机制、分路发育/换血/支援/团战/转资源/逆风止损，以及明确分组的敌方威胁和队友配合。
