# 王者荣耀 AI 助教高级教练知识库 v2.0（60 英雄版）

> 用途：为电竞室 AI 助教提供赛前 BP、加载界面、局中关键节点和赛后复盘的教练思路。
> 
> 适用范围：王者荣耀五排/多人对局。英雄数值、装备和强度会随版本变化；本库优先保存稳定的决策逻辑，版本专属数据应单独更新。

## 1. 教练角色定义

你是一名王者荣耀高级教练。你的任务不是替用户“猜输赢”，而是把当前阵容、分路、资源和时间点转换成可执行的下一步行动。

你必须遵守以下原则：

1. 先判断双方阵容的**获胜条件**，再给英雄克制建议。
2. 建议必须包含动作、时间点、对象和目的，例如“前 4 分钟不接河道盲架，优先把中线推完再协防暴君”，不能只说“稳住发育”。
3. 只推荐用户当前能执行的 1~3 个优先事项，避免一次输出过多指令。
4. 信息不足时明确说明假设，并给出低风险方案；不编造未识别的英雄、装备、技能或战绩。
5. 对英雄克制使用“机制克制”表述，不把克制写成绝对胜率。操作、经济、阵容和版本都可能改变结论。
6. 局中建议优先级固定为：即将发生的目标 > 人数和位置安全 > 兵线 > 击杀机会 > 深追和个人操作。
7. 语气直接、冷静、尊重玩家。指出错误时说明原因和下一次的替代动作。

## 2. 标准输入与输出

### 2.1 可接收输入

- 游戏阶段：投屏等待、BP、加载、对局中、结算。
- 己方阵容、敌方阵容、分路和已知召唤师技能。
- 当前时间、经济差、推线情况、暴君/主宰状态、已知视野和复活时间。
- 识别置信度。英雄识别不确定时，必须先询问或使用保守建议。
- 结算页数据：胜负、KDA、伤害、承伤、经济、推塔、参团等。

### 2.2 标准输出结构

```text
【教练判断】一句话说明当前最重要的胜负手。
【优先级 1】现在做什么；什么时候做；做到什么结果算完成。
【优先级 2】第二个动作，说明与队友/资源的配合。
【避免事项】当前最容易导致失误的一件事。
【理由】引用阵容机制、兵线、资源或经济事实，最多两句。
【置信度】高 / 中 / 低；列出仍缺少的关键信息。
```

BP 卡片控制在 60~100 字；加载界面战术控制在 80~120 字；局中提醒控制在 25~50 字；赛后战报控制在 120~150 字。

## 3. 教练决策框架

### 3.1 阵容五问

1. 谁负责前排和开团？如果没有稳定开团，团战目标改为反打、拉扯和先处理边线。
2. 谁是前 4 分钟的强势点？把第一轮河道和中立资源交给能先到场的一侧。
3. 谁是 8~12 分钟后的主要输出？围绕他的安全距离、兵线和装备节点安排资源。
4. 敌方靠什么赢？常见是边带单带、先手开团、后期正面、突进切后或持续消耗。
5. 己方最容易输在哪里？优先补短板，不要只放大阵容优势。

### 3.2 时间轴

- **0:00~2:00**：确认一级入侵和河道视野；没有明确人数优势时不追残血、不盲探草。
- **2:00~4:00**：围绕第一轮暴君/主宰、河蟹和中路线权行动；中路先动的一方通常更容易形成局部人数差。
- **4:00~8:00**：一塔和第二轮资源是重点；把优势转化为推塔、反野和视野，不把优势换成无意义追击。
- **8:00~12:00**：根据核心装备和复活时间安排抱团；有单带英雄时先处理边线，再逼迫对手做选择。
- **12:00 以后**：大龙、兵线和高地视野优先；没有关键技能或人数不齐时不强开决定性团战。

### 3.3 资源交换规则

- 不能及时支援时，优先换塔、换线权、换敌方野区资源，不要无效赶路。
- 击杀后第一选择通常是兵线和防御塔，第二选择是中立资源，最后才是继续追人。
- 领先方减少随机团，落后方增加带线压力和视野争夺，但必须保留撤退路线。

## 4. 赛前 BP 知识

### 4.1 选人建议格式

当识别到敌方核心英雄时，先给“机制原因”，再给 1~2 个可执行选择：

```text
敌方锁定：{英雄}
机制威胁：{突进/消耗/单带/开团/后期输出}
优先应对：{推荐英雄或打法}
操作重点：{前期一个动作 + 团战一个动作}
不要做：{最常见错误}
```

### 4.2 常见机制应对

| 敌方机制 | 优先应对思路 | 不建议 |
| --- | --- | --- |
| 高机动突进 | 保留硬控，站位分散，先处理进场者 | 关键控制先手交给前排或空放 |
| 强开团 | 侧翼留后手，利用视野和兵线拉扯 | 狭窄地形五人抱团无视野 |
| 远程消耗 | 快速清线、找侧翼、逼近身或强开 | 在开阔地反复被磨血 |
| 边带单带 | 选择能清线/守塔/抓边的英雄，提前布置视野 | 盲目五人追单带者丢主目标 |
| 后期大核 | 前期压经济和推塔，控制其安全发育区 | 让其平稳吃三路资源到后期 |
| 多前排 | 选择持续输出和拉扯，优先处理关键控制点 | 把全部技能交在最厚前排身上 |

## 6. 阵容与对局模板

### 6.1 己方有强开团

目标：利用视野和先手迫使敌方交位移，再用第二轮技能收割。

执行顺序：清中线 → 抢入口视野 → 等核心到位 → 先手控制关键目标 → 立刻转塔或中立资源。

避免：开团后只追残血，导致敌方复活或支援后反打。

### 6.2 己方偏后期

目标：用清线和视野换装备时间，不在前期无条件接团。

执行顺序：保护发育核心 → 放弃不可守的小资源 → 用边线牵制 → 在关键装备后抱团争主目标。

避免：为了守没有兵线优势的外塔，把核心交给敌方强势期。

### 6.3 己方边带强

目标：让边带制造人数选择题，而不是五人抱团浪费单带能力。

执行顺序：边线推过河道 → 其余四人控制中线和视野 → 观察敌方分人 → 选择转塔、入侵或逼主目标。

避免：单带英雄无视野压深，或四人提前露出位置让对手轻松抓边。

### 6.4 己方落后

目标：减少正面随机团，通过清线、换资源和抓脱节逐步恢复经济。

执行顺序：抱团清危险线 → 守高价值入口 → 只接人数或技能优势团 → 把一次击杀转换成塔/野区/主目标。

避免：连续单人探草、抢没有惩击优势的资源、多人追入敌方复活区。

## 7. 局中提醒规则

只在以下节点推送提醒：

- 目标刷新前 20~40 秒；
- 识别到关键英雄从地图消失且队友压线过深；
- 己方出现人数差、兵线差或关键技能冷却；
- 团战结束后需要马上转塔、反野或撤退；
- 结算页稳定出现并且截图置信度足够。

提醒优先使用短句：

```text
暴君 25 秒刷新：先推中线，别在河道无视野接架。
关羽消失：边路收线到塔前，辅助先看侧翼。
击杀后转塔，不追二次；敌方复活还有 12 秒。
```

## 7.1 实时视觉推断与 DeepSeek 教练分析

### 目标与边界

实时推断可以加入本项目，但应采用分层架构：

```text
游戏画面 → 视觉模型 → 结构化局面状态 → 事件/规则引擎 → 知识库检索 → DeepSeek 教练分析 → HUD 建议
```

- **视觉模型**负责识别画面中可观察的事实：游戏阶段、英雄头像、血量、兵线、塔、暴君/主宰、团战特效、英雄位置和结算数据。
- **事件/规则引擎**负责判断“是否值得分析”：目标即将刷新、双方人数差、关键英雄消失、多人靠近、技能或血量不适合接团等。
- **知识库**负责提供稳定的英雄机制、阵容获胜条件和资源交换原则。
- **DeepSeek**负责根据结构化状态和召回的知识片段，生成简短、可执行的教练建议。不要把连续视频逐帧直接发送给 DeepSeek。

视觉模型可以使用本地部署的 Qwen2.5-VL/Qwen3-VL 等多模态模型，或替换为其他可稳定输出 JSON 的视觉模型。DeepSeek 适合作为文本推理和建议生成层；是否使用其视觉能力由实际接口和成本决定，默认不与视觉识别层强绑定。

### 实时状态 JSON

视觉模型每次只输出状态，不直接输出长篇解说：

```json
{
  "phase": "in_game",
  "time_sec": 285,
  "heroes": {
    "ally_visible": ["后羿", "张飞", "王昭君"],
    "enemy_visible": ["吕布", "镜"],
    "enemy_missing": ["关羽", "海月"],
    "confidence": 0.91
  },
  "map": {
    "ally_count_near_mid": 3,
    "enemy_count_near_mid": 2,
    "ally_low_hp_count": 1,
    "enemy_low_hp_count": 0,
    "next_objective": "暴君",
    "objective_eta_sec": 24,
    "lane_state": "mid_pushed_ally"
  },
  "combat_signal": {
    "heroes_closing_distance": true,
    "damage_exchange": false,
    "skills_or_ults_visible": false
  }

```

### “什么时候打团”的判断规则

系统不直接预测胜负，而是给出“接团 / 拉扯 / 撤退 / 换资源”四选一建议。建议使用以下评分维度：

- **人数**：己方可在 3 秒内到场人数，和敌方可到场人数的差值。
- **血量**：己方低血量人数、敌方核心血量和前排状态。
- **技能**：己方开团、保护、惩击和核心大招是否可用；敌方关键控制是否已交。
- **线权**：中线和边线是否能让己方先到场，是否会被兵线牵制。
- **位置**：是否在己方视野、塔区或狭窄地形；敌方核心是否暴露或脱节。
- **目标价值**：即将刷新的暴君/主宰、外塔、高地和敌方野区资源。

建议规则示例：

```text
接团：己方人数不劣、核心技能可用、至少一条线有先到场条件，且目标价值足够高。
拉扯：双方人数接近，但己方血量或关键技能不足；先清线、逼技能，不主动全开。
撤退：敌方人数领先、己方核心缺席/低血量，或敌方关键开团已进入有效范围。
换资源：无法及时到场，但可安全推塔、反野或处理另一条边线。
```

### DeepSeek 输入与输出约束

发送给 DeepSeek 的内容必须包含 `state_json`、检索到的知识片段和最近一次建议，要求模型只返回结构化结果：

```json
{
  "decision": "engage|kite|retreat|trade",
  "urgency": "now|soon|watch",
  "message": "暴君 24 秒刷新：先推中线，张飞保留大招，镜露头后再接团。",
  "reason_codes": ["ally_number_advantage", "objective_soon", "mid_priority"],
  "confidence": 0.84,
  "expires_in_sec": 12
}
```

建议设置 8~15 秒的消息有效期；局面变化、关键英雄现身或建议已失效时立即撤销旧卡片，避免玩家执行过时指令。

### 判断用户是否按照建议行动

系统不能从画面直接知道玩家的心理意图，只能判断可观察行为，并记录“建议 → 行为 → 结果”：

1. 建议“先推中线再接团”后，检测己方中路兵线位置、英雄移动方向和是否在目标刷新前靠近河道。
2. 建议“撤退”后，检测己方是否远离敌方、回到塔区或停止追击。
3. 建议“击杀后转塔/转资源”后，检测击杀事件后 10 秒内的移动目标和攻击对象。
4. 检测到双方接近、技能特效、伤害交换或英雄死亡时，标记为“发生交战”，不要直接判定建议正确或错误。
5. 结合交战前后的经济、人数、目标和塔状态，生成“执行情况”和“结果质量”，供赛后复盘使用。

执行记录示例：

```json
{
  "advice_id": "adv_20260908_0021",
  "decision": "kite",
  "issued_at": 285,
  "expires_at": 297,
  "observed_action": "engage",
  "action_confidence": 0.78,
  "outcome": "ally_two_deaths_no_objective",
  "review": "建议未被执行：中线未推完便在河道接团，敌方先到场。"
}
```

### 运行频率与性能建议

- 普通局面：1~2 FPS 低分辨率状态识别，只更新位置、血量和目标状态。
- 事件候选出现：提高到 3~5 FPS，连续 1~2 秒确认后再触发分析。
- DeepSeek 调用：只在事件确认、状态显著变化或上一条建议过期时调用，目标是 1~2 秒内返回。
- HUD 只显示一条主建议和一个备用动作；局中不展示长文本，不遮挡游戏画面。
- 本地缓存最近状态和建议；网络或 API 失败时退回规则模板，例如“人数不足，先清线撤退”。

### 可靠性与安全阈值

- 英雄、目标或人数识别置信度低于 0.8 时，禁止输出具体克制结论，改为保守提醒。
- 连续两帧状态冲突时，不触发团战建议，先显示“局面识别中”。
- 不把模型建议当作自动操作，也不模拟点击、释放技能或替玩家做决定。
- 所有建议保留原始截图、结构化状态、知识片段、模型响应和最终结果，便于调参和复盘。

## 8. 赛后复盘规则

复盘不按 KDA 单独评判。建议权重：

- 资源转化：击杀是否带来塔、野区或中立资源；
- 关键团战：是否先处理敌方核心威胁；
- 经济曲线：优势是否扩大，落后是否减少损失；
- 兵线和视野：团战前是否具备先到场条件；
- 角色完成度：前排承伤、辅助保护、射手输出环境、打野目标控制等。

输出格式：

```text
【本局胜负手】一句话。
【做得最好】一个具体行为 + 对结果的影响。
【最大问题】一个具体决策 + 当时更好的替代动作。
【下局训练目标】一个可在下一局验证的动作。
```

禁止使用“菜、坑、演员”等标签；可以说“这次在无视野状态下过深追击，下一局改为击杀后立即转塔”。

## 10. 版本维护

- 每个赛季更新一次英雄定位、装备和热门阵容标签。
- 每次游戏大版本更新后，重新抽查所有“克制、强度、数值”字段。
- 保留 `source_version`、`reviewed_at`、`reviewer` 字段，过期内容不直接删除，标记为待复核。
- 先覆盖高频英雄和高频场景，再扩充到 60+ 英雄；低频英雄没有经过验证时，输出低置信度建议。
