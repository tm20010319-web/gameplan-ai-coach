# 敌方大招、闪现自动监控

更新：2026-09-17。本机 Ollama 使用 `qwen3-vl:8b-instruct`，配合 OCR、短时跟踪与图标比对。采集、识别、字幕和预计冷却流程已接通；全部英雄精度、真实闪现正例以及稳定在 8 秒内提醒尚未验收通过。

## 使用

手机通过 USB 或无线投屏到 Windows，打开 `http://127.0.0.1:8767/monitor`。首次选择游戏投屏窗口，保持“打开此窗口时自动开始”勾选；预热模型后自动采集，以后沿用保存的来源。断开、最小化或黑屏时等待同一来源恢复，停止按钮可取消等待，不会改抓其他屏幕。窗口标题或类型改变可能需要重新选择。选择本地视频也先预热，再边播放边识别。

正常流程无需逐人手动标记技能。系统自动利用可读的加载卡片、战绩面板建立本局英雄与昵称对应。未看到这些证据、版式不支持或遮挡时，身份和携带技能可能一直待确认。手动更正保留为可选补救。

## 本轮实现

- 移除外层页面强制关闭自动启动的参数，保留用户明确关闭的选择。
- 增加 Windows 窗口采集、记住来源、断开重连、停止等待、来源切换清局。接口不返回原生窗口句柄；Pillow 最低版本同步更新。
- 请求统一使用 16384 上下文并在开始前预热，避免不同帧数切换上下文导致反复重载和加载超时。
- 缓存最近 7.5 秒，最多提交 8 帧（CPU 4 帧），不再只分析末尾两帧。长序列相邻帧上下排版并标记 F 编号，结果映射回真实采集索引。
- 核对首尾、中间帧，未见目标时继续查剩余帧。光流只短暂延续已有身份，不创造身份。剩余预算内可对一处明显变化做两帧细查。
- 本局缓存相同画面的 OCR，身份改变后重读，缓存有容量限制，重置后清空。
- 支持双排加载卡片，以唯一的本地昵称高亮确定己方，不默认上排是己方。保留艾琳及已核对的完整阵容，不因一帧漏字把五人缩成四人。
- 加载图标核对中心、形状、候选差值与颜色，连续三次一致才确认。弱结果、缺失、冲突中断待确认序列，不把匹配分数提升成 1.0。
- 修正短昵称的等级定位，孙策样本的 13 级可读。不从比赛时间或特效猜等级。
- 敖隐化龙须有相符形态证据；声称变身时仍能读到正常名字则不确认。闪现另需前后同一角色和扣除镜头移动后的位移，变身消失不算闪现。
- 只读取完整最终回答，超时、缺少结果及未完成检查会显示状态。没有本地身份时只发现阶段与阵容，省去无效多帧技能猜测。

提醒目标为 8 秒，处理保护时限约 12 秒，允许接近完成的判断返回；超目标如实显示。首次预热另需等待。这不等于已经达到 8 秒端到端验收。
