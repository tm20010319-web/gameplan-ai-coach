# 自动个人复盘

在 `/monitor` 或置顶小面板中选择游戏窗口并开始监控。系统自动区分王者荣耀与英雄联盟端游，按局记录当前操控英雄，连续确认明确的胜利/失败画面后，在“本局复盘”生成至多两条“问题＋下局做法”。“历史复盘”支持分页查看，建议可展开对应的关键画面。

## 记录和生成

- 本机 Ollama 提取游戏类型、阶段、玩家视角、操控英雄、可见时间和最多三条个人事实。王者荣耀约每 12 秒安排一次复盘采样，其他轮次保留原技能识别流程；英雄联盟使用共用复盘识别，不套用王者荣耀的技能计时或打法。
- 采集仍持续进行，分析只读取最新送检画面及最多两张近期画面，不积压整局视频。性能和事件覆盖取决于本机模型速度；采样可能漏过短暂事件。
- 连续两次确认游戏内容后创建对局，连续两次确认操控英雄后绑定个人身份；中途镜头中的其他英雄不替换玩家。观战画面不产生个人事实。
- 只有已记录至少两次玩家局内观察，且两次间隔 1–90 秒的识别一致读到胜利/失败，才结束该局。Tab 战绩、死亡、切桌面和单次不确定结果不触发结束。
- 进入下一局选人/加载、连续确认游戏切换或对局时钟明显回退，会切分新局；没有采到结束画面的上一局保留为“未确认结束”，不编造胜负。手动新对局或切换采集源也保留之前的记录。
- DeepSeek 每局只自动提交一个分析任务；失败显示“待重试”，不会冒充成功。任务处理中刷新页面不会重复调用；服务中断留下的任务可恢复。个人事实不足时明确显示“记录不足”。
- 每条问题最多 45 字，改进最多 55 字，最多两条。生成结果必须引用本局个人事实编号。仅有局部证据时要求限定范围；无法证明失误时用“待核对”。模型文字仍须结合实际画面判断。

## 配置与存储

复用项目 `.env` 中的 `OLLAMA_URL`、`OLLAMA_VISION_MODEL` 和 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`，不增加另一套密钥。DeepSeek 配置按请求读取。

`data/reviews.sqlite3` 保存对局、处理状态、事实和 JPEG 采样；配置 `COACH_DATA_DIR` 时随之改变目录。每局最多保存 480 张压缩采样，优先保留结束、交战和目标画面；历史对局不自动删除，长期使用会增长。画面可能包含游戏内昵称；仅在本机保存，只把筛选后的游戏事实发送给 DeepSeek。截图不发送到 DeepSeek。

复盘 API 限本机同源访问：

| 接口 | 用途 |
| --- | --- |
| `POST /api/vision/observe` | 实时请求带 `auto_review: true` 接入自动记录 |
| `GET /api/reviews?limit=10&offset=0` | 历史列表 |
| `GET /api/reviews/streams/{stream_id}` | 当前采集会话的最新对局 |
| `GET /api/reviews/{match_id}` | 卡片与采样事实 |
| `GET /api/reviews/frames/{frame_id}` | 本地关键画面 |
| `POST /api/reviews/{match_id}/retry` | 重试失败的分析 |
| `POST /api/reviews/streams/{stream_id}/close` | 切换采集时保留未结束的对局 |

页面刷新通过当前浏览器标签的 sessionStorage 恢复采集会话。关闭后新开标签不会自动关联旧的进行中对局，历史复盘仍可查看。上传视频和单张图片沿用原流程，不自动登记为本人新的一局。

## 验证边界

生命周期、隔离、持久化、接口权限、故障恢复、简短输出约束和页面交互已进行自动化测试；真实 DeepSeek 接口已用明确的示例事实联调。尚未以两款游戏的完整真实对局验收视觉识别率、结算停留时间或对游戏帧率的影响。要自动复盘，需要持续监控游戏窗口，并让结束画面保持可见直到识别确认。
