# 小象助手文字聊天

## 已实现范围

打开 `http://127.0.0.1:8767/chat`。原工作台、独立监控、技能面板和两个知识库页面均提供入口；监控页“小象助手 · 聊天问答”可展开直接聊天。已有文字技能计时仍使用原入口。

本次实现文字聊天；按用户要求，没有接入或开发语音模块、语音专用接口、录音、转写和播报。

- 自动从英雄官方名、称号、英文名及已有别名/有限错字映射判断游戏和英雄。
- 同名英雄、共享称呼无法确定时先询问，可点击候选确认；保留原问题，确认后继续回答。
- 记住当前英雄，例如“剑魔怎么打”后可问“他的大招多久”；明确出现另一款游戏的英雄时切换。支持冷却问题后接“那 Q 呢”。
- 本地会话保留最近二十轮，刷新可恢复。新对话使用新的编号和上下文，旧对话仍保存在本机，但本次不提供历史会话列表。
- 回答以简短文字为主，展开可看所引用原文、版本和知识库页面。
- 装备全名可检索现有属性/价格，英雄背景可检索英雄联盟已有故事资料；这些已收录内容同样先在本地处理。

## 王者英雄别名与聊天计时

复用知识库已有的 132 位英雄、335 条常见别名及单独维护的同音/错字映射；每位英雄的知识库页面可查看别名，也可按别名搜索。聊天问答和计时共用同一别名目录。共享别名（如“鲁班”）先确认具体英雄；不会直接选中第一位。

在聊天中发送“小明大招用了”“小明用了大招”“妲己放大了”“他的一技能用了”或“小明闪现了”，按本地资料立即计时，不调用外部模型。支持全部王者英雄的大招、已收录的一至四技能和闪现；默认技能一级、基础冷却、零冷却缩减。以服务收到该次指令的时间作为起点，不扣除原文字计时模块的三秒报时补偿。有歧义时，在确认收到后起算。

聊天上方显示独立倒计时卡片，到期提示“某英雄某技能预计已好”；不代表识别到游戏内真实冷却。技能刷新、冷却缩减和特殊条件可能改变实际可用时间。动态、待复核或没有有效数值的技能只记录使用并显示“冷却未知”，不会让模型编造秒数。当前未接入语音录制或播报，文字指令可以来自将来接入的语音转写。

同一英雄同一技能再次报使用会重新计时；不同英雄和技能分别保留。取消卡片或发送“取消明世隐大招计时”可移除记录，“清空计时器”清空当前对话。计时状态独立于最近二十轮聊天保存，刷新按截止时间恢复，不重新开始；同一请求重试不重置。新对话使用独立计时列表。到期提示在聊天页面打开时显示，关闭页面期间不发送系统通知，重新打开时显示当前状态。

“孙策没大招”“孙策没大招了”“小明没有大招了”“小明大招没了”“小明没大了”也视为大招计时报告，按用户约定从收到报告时开始完整默认冷却倒计时。“没大招”并不能推断真实施放时间，因此仍显示为估算；“还没用大招”、疑问句和假设句不作为施放报告。这些表达适用于全部王者英雄及已收录别名，共享别名依旧先确认。

支持一条消息报多个英雄，例如“小明没大招，诸葛亮也没大”“小明和诸葛亮都没大招”，以及分别报不同技能。逗号、分号、换行可分隔独立报告，顿号或“和/与/跟”可连接共用一个技能报告的英雄。明确识别的英雄按同一个接收时间分别计时；歧义名字逐个询问，未知名字可回复全名纠正。确认只启动该条待确认计时，不重置已开始的其他计时。待确认列表随会话保存；“取消确认”放弃尚未确认项，“清空计时器”同时清空计时和待确认项。

## 英雄联盟大招与闪现计时

英雄联盟端游复用上述别名识别、多英雄报时、歧义确认、持久化、重试去重及五列紧凑卡片。当前仅支持大招（也可说 R）和闪现，Q/W/E 不启动计时。例如“寒冰没大招，剑魔闪现用了”“寒冰 R 用了”“寒冰没闪”。“大招好了”仍不是重新计时口令。

全部 173 位英雄的大招从本地 `lol_catalog.json` 读取一级基础冷却；缺失、零值、动态或待核验的冷却只记录使用，不伪造倒计时。闪现来自同版本 Riot Data Dragon `summoner.json`，本地保存于 `lol_summoner_spells.json`，召唤师峡谷默认 300 秒。未计技能/召唤师技能急速、符文、装备、刷新及特殊模式修正。

计时使用游戏、英雄 ID、技能标识共同区分。卡片标注所属游戏，取消时也带上游戏名；王者和联盟的同名英雄可同时保留，既有王者计时可继续恢复。

并列名单也可共用末尾动作：“盖伦，盲僧没大招”同时给盖伦和李青计时，“盖伦，寒冰，盲僧闪现用了”同时记录三人的闪现。只让连续、可识别的纯英雄名称承接后面的明确施放报告；疑问句、否定施放、其他内容或没有后续动作时，不从单独名字推测计时。

支持同一组英雄一次报告大招和闪现：“奶妈，牛头，阿狸没大没闪”“奶妈、牛头和阿狸大招和闪现都用了”会分别记录三人的两个技能，共六个独立计时。“没大招也没闪现”“没有大招和闪现”同样支持。后续独立英雄报告只使用自己的技能项，不继承前面一组的全部技能；重复报告同一个英雄技能只登记一次。歧义名字的多个技能合并为一次确认，确认后同时启动，不重放已明确英雄的记录。

## 检索与补充

数据来自现有 `skill_catalog.json`、别名和装备目录、技能知识模块中的教练资料，以及 `lol_catalog.json`；王者荣耀通用原则取自 `knowledge_base.json`。这不是对项目所有 Markdown 文件的任意全文搜索。

明确的冷却、技能、装备等事实问题直接选择相关条目并整理短回答，不调用模型。复杂问题先交本机 Ollama 从已有段落中选择最多三条依据并判断缺失项。模型只返回受校验的段落编号，回答正文从原文整理，防止它自行增加“知识库事实”。这依然是语义检索，相关性与覆盖判断不能保证每次正确。

只有检索确实没有结果、字段缺失、冷却待核对，或本地语义核对报告部分问题无依据时，才调用外部模型补充缺失部分。本地内容单独保留，不被外部回答替换；补充内容明确标为模型知识，未联网核验，不自动写回知识库。

本地模型暂不可用不等于资料缺失：保留相关原文，并提示暂时未能完成语义核对，不仅因本地故障就外发资料。外部接口不可用时保留本地答案，并显示失败状态。

## 模型配置

本地配置：

```dotenv
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_CHAT_MODEL=qwen3-vl:4b-instruct
```

本机已存在上述 4B 模型，没有额外安装。聊天只允许本地回环地址的 Ollama，避免把“本地整理”意外发送到远端。首次加载可能较慢；本地请求超时 30 秒。

外部模型复用 `gameplan/tactics/personal_plan.py` 的 `text_model_config()`：读取 `.env` 中 `COACH_PROVIDER`、`COACH_BASE_URL`、`COACH_MODEL`、`COACH_API_KEY`；未覆盖时使用既有 DeepSeek / Qwen / Doubao 对应配置。密钥不返回前端。接口地址必须为 HTTPS，外部请求超时 40 秒。

外部请求只含当前问题、缺失项、相关资料、已确认游戏/英雄和最近最多四轮对话，不发送截图、录音或其他工作区文件。聊天接口仅允许本机同源访问。

豆包聊天补充使用 Ark `/responses`，DeepSeek / Qwen 继续使用 `/chat/completions`。本机配置为：

```dotenv
COACH_PROVIDER=doubao
COACH_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
COACH_MODEL=doubao-seed-2-1-pro-260915
# ARK_API_KEY 仅保存在本机 .env；如有 COACH_API_KEY 覆盖项，须与当前密钥保持一致。
```

Responses 请求使用提示词要求 JSON，客户端严格校验 answer 字段与长度，不依赖模型的结构化输出选项。仅接受已完成响应中的助手 output_text，排除推理过程；未完成、拒绝、工具输出和非法答案均不作为补充展示。请求关闭思考与响应存储。此 Responses 适配限于聊天补充，原个性化方案功能仍沿用其既有调用方式。

2026-09-28 实测：已按用户提供的最新调用示例切换至 `doubao-seed-2-1-pro-260915`，真实 Responses 调用成功。运行中的聊天服务验证：“剑魔大招冷却多久”返回本地资料且 external_status=not_needed；“安妮出装和符文”保留本地出装资料并获得豆包补充，返回 status=hybrid、external_status=used，模型字段确认是 Pro 2.1。配置逐次读取，无需重启服务。先前 Pro 2.0 的模型访问 404 已不再阻塞当前配置；真实调用成功不代表模型补充经过当前游戏版本核验。

## 保存与接口

`data/chat.sqlite3` 独立保存会话。可用 `COACH_DATA_DIR` 改变数据目录。SQLite 租约防止同一对话并发覆盖；请求编号用于最近二十轮内的重试去重，重试不会重复生成答案或重复调用模型。回答完成后才更新上下文。过期请求不能覆盖后续轮次。

- `POST /api/chat/sessions`：创建对话。
- `GET /api/chat/sessions/{id}`：恢复上下文和最近二十轮。
- `POST /api/chat/sessions/{id}/messages`：发送普通文字消息，参数 `text`、`request_id`、`revision`。
- 回复含 `answer`、`sources`、`status`、`external_status` 等字段，来源状态包括本地、混合、模型补充、待确认、部分回答。

前端遇到失败可重试；开始新对话会丢弃旧请求的晚到结果。浏览器只保存当前会话编号，正文在本机数据库中。
