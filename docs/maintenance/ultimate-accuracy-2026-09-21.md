## 复现与对照

使用已有真实录像、截图及本地 `qwen3-vl:8b-instruct`。先运行原检测器：

```powershell
.\.venv\Scripts\python.exe work\live-video-audit-20260920\probe.py --times 151.3,151.6,152 --tag accuracy-baseline-20260921 --expect 墨子:墨守成规
```

结果为 `AssertionError: MISSED_ENEMY_CAST: 墨子:墨守成规`。模型将角色误认为吕布，且报错帧号。缩减为 152 秒单帧仍失败，模型编造了不在敌方名单内的角色与技能。一次冷启动模型加载约 5.96 秒，不能将这次耗时直接用于热启动性能比较。

在同一张真实画面上逐项实验：

1. 只放大敌方局部、沿用原长提示：仍然误认。
2. 放大局部、精简提示：看到了菱形屏障，但没有认成大招。
3. 增加墨子四边形电能屏障与普通护盾/炮弹的视觉区别：正确报告墨子大招。
4. 相同视觉说明换回整屏图：也命中。由此不能把此样本的失败全部归因于分辨率；技能说明与画面特征之间的联系是重要因素。

这些实验未注入英雄身份、施放事件或模型回答。候选敌方名单来自既有录像核对，用于隔离技能检测器，不代表重建了历史服务的全部内存状态。

## 实现

- `skill_effect_input.py` 根据本帧实际定位的敌方角色裁取周边战场，保留领域、附近角色和血条。多目标使用联合区域。没有定位到敌方的帧不再混入模型拼图；原始 F 帧号和 A 目标编号保持不变。
- 模型输入以可见外形和技能区别为主，去掉冗长的召唤师数值说明。墨子、吕布、孙策、敖隐、妲己补充了视觉参考，其余英雄仍使用目录机制说明。新增参考不等于这些英雄全部通过实战验证。
- 用 JSON Schema 限定可输出的英雄、目标编号、原始帧号和技能名称；跨帧归属、敌我身份及技能携带矛盾仍由本地规则检查。
- 模型回答明确写“疑似”“无法确定”等时，不能靠高置信分数直接进入确认记录。
- 对上述五位英雄检查证据文字是否描述了必要的专属特征。例如只写普通挥戟、扇形轨迹和伤害数字不能确认吕布大招。**这是文字证据完整性检查，不是独立图像分类器，也不能排除模型编造特征。**
- 裁剪后不再把原整屏百分比坐标作为局部图位置提示。原坐标只保留在诊断记录中。
- 延迟目标、共享 OCR/模型处理预算及 `over_target` 标记统一使用 10 秒。实际投屏延迟、等待和冷启动仍需测量；超时不代表没有释放。
- 保留现有单帧明确特效策略、确认记录去重和按首次可见特效画面计时；未更改冷却知识数值。
