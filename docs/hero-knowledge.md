# 英雄外部知识库

知识库文件：`data/hero_knowledge.sqlite3`。独立于 Ollama 模型权重，可使用 SQLite 工具直接查询 `heroes(name, data)`，data 是带来源的 JSON。

识别流程：Ollama/本地识别 → 官方英雄名精确查询 SQLite → 技能与带来源的条件性打法。独立监控使用本地规则；工作台配置了 DeepSeek 时将知识作为 K 编号依据传给模型，没有配置时也使用已匹配的攻略作为本地参考。基础冷却不代表画面中的剩余冷却。

数据优先来自腾讯官网制胜宝典的结构化接口 `https://pvp.qq.com/zlkdatasys/zsbd_herolist/{英雄ID}.json`，PC 和手机详情页作为备用。包含英雄名、ID、官方定位编号、被动、主动和附加技能、技能描述、基础冷却、来源和抓取时间。已有战术参考另外标记为定性资料。官网未明确标注对局版本。

更新：在项目根目录执行 `.venv\Scripts\python.exe scripts/update_skill_catalog.py`。查询时按源文件版本自动同步 SQLite。失败的抓取保留已有有效资料及原始时间。

2026-09-16 已收录官网目录全部 132 个英雄条目（含元流之子分支、命格），共 537 条技能；132 个条目均有大招与冷却资料。心魔六耳、卢雅那已通过结构化接口补齐。大乔、干将莫邪、女娲、元歌、敖隐用 `is_ultimate` 标识第四技能大招；大禹、元流之子等不再从图片编号猜技能槽位。完整列表见 [技能与大招冷却索引](英雄技能与大招冷却索引.md)。

冷却字段保留 `cooldown_text` 原式，`base_cooldowns_s` / 查询接口的 `cooldown_s` 为按技能等级排列的秒数。`cooldown_kind=level_formula` 由官网1级基值及每次升级递减量展开，公式保存在 `cooldown_formula`。朵莉亚为 `dynamic`，按 10/9/8 + 120% × 目标技能当前冷却计算，不能直接取 10 秒作为总冷却。鲁班大师的官网大招字段有六档数值，与历史官网条目不一致，标记 `cooldown_review_required` 并保留历史来源，暂不用于倒计时。

接口覆盖统计增加技能总数、大招覆盖、冷却覆盖、动态公式和来源待核对名单。基础资料齐全不等于所有形态、技能等级和当前版本均已实战验证。

查询接口：`GET /api/knowledge/skills/status`、`GET /api/knowledge/skills/廉颇`、`POST /api/knowledge/skills/lookup`（JSON：`{"heroes":["廉颇","敖隐"]}`）。

## 五位常用英雄

李元芳打野、伽罗和艾琳发育路、小乔中路、吕布对抗路。默认配置以用户确认的截图和文字为准，不等同于本局已携带。五位共38条规则，每条带稳定编号、适用条件、来源、类型、优先级及所需分路。官方提示、第三方文章和用户文字分别标注，原始资料留档。

本地建议只针对已确定的操控英雄选择规则；缺少分路时不使用限定打野的规则，当前读数显示技能冷却时跳过依赖该技能的规则。队友与对手不在已知阵容中的具名配合不推荐。未知视野、兵线、队友跟进等条件保留为“若……”的条件参考，不能声称已满足；规则优先级不是实时危险检测。

艾琳伤害类型与属性转换存在来源冲突，当前版本未核验。缺失与冲突见 [完整性报告](knowledge-audit.md)。小件购买顺序、逆风或针对阵容换装按用户要求排除。未读取的视频、贴吧正文及待审核文档不会自动变成有效攻略。

运行 `.venv\Scripts\python.exe scripts/audit_hero_knowledge.py` 可重新生成 Markdown/JSON 报告，不联网更新资料。监控与工作台均提供上述 GET 查询接口；批量 POST 查询目前由工作台提供。
