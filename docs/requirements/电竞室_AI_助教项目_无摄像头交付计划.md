# 电竞室 AI 助教项目迭代计划（MVP + 知识库增强版）

本文档为电竞室 AI 助教项目的落地实施方案。在**不引入语音播报与复杂硬件联动**的前提下，引入**英雄克制与对战战术知识库**，通过赛前精准检索生成高质量战术建议，实现低延迟、低复杂度的轻量级完整闭环。

---

## 一、方案核心原则

- **无语音、无复杂硬件负担**：彻底剔除语音合成（TTS）、音箱播报与 IoT 智能灯光联动，所有战术指导统一在大屏侧边 HUD / 战术卡片以文字和图表呈现。
- **引入战术知识库（赛前核心支撑）**：构建英雄克制弱点、对线攻防策略、团战核心切入点的结构化战术知识库。赛前识别英雄后，检索匹配专业战术策略，由大模型或模板快速输出高专业度对战思路。
- **局中默认不打扰，只在高价值事件提醒**：局中不做逐帧解说和高频弹窗，只在目标刷新、人数差、关键英雄消失、多人接近和团战前兆等事件触发一条短建议，全流程聚焦在：
  1. **底座**：低延迟大屏投屏与 HUD 框架
  2. **赛前**：选人/加载界面的知识库战术检索与大屏卡片推荐
  3. **局中事件推断**：视觉模型低频观察局面，只在目标刷新、人数差、关键英雄消失和团战前兆等节点触发分析
  4. **赛后**：静止结算大图识别与趣味深度战报出图扫码

- **视觉模型与 DeepSeek 分层**：视觉模型输出英雄、位置、血量、兵线、目标和交战信号等结构化状态；规则引擎筛选高价值事件；知识库提供战术事实；DeepSeek 负责生成教练口吻的短建议。实时视频不逐帧直接发送给大模型。

## 三、实时视觉推理与 DeepSeek 接入方案

### 3.1 推荐系统架构

```text
游戏投屏画面
    ↓
OpenCV / 视频流采样
    ↓
视觉模型（Qwen2.5-VL / Qwen3-VL 等）
    ↓ 输出结构化状态 JSON
事件规则引擎（目标、人数、血量、线权、技能、位置）
    ↓
高级教练知识库检索
    ↓
DeepSeek 文本推理接口
    ↓ 输出接团 / 拉扯 / 撤退 / 换资源
WebSocket → 大屏 HUD
```

视觉模型负责“看见事实”，规则引擎负责判断是否值得触发，知识库负责提供稳定战术，DeepSeek 负责把事实和知识压缩成玩家能立刻执行的一句话。

### 3.2 实时推理输入

视觉模型应输出结构化字段，而不是长篇描述：

```json
{
  "phase": "in_game",
  "time_sec": 285,
  "ally_visible": ["后羿", "张飞", "王昭君"],
  "enemy_visible": ["吕布", "镜"],
  "enemy_missing": ["关羽", "海月"],
  "ally_count_near_mid": 3,
  "enemy_count_near_mid": 2,
  "ally_low_hp_count": 1,
  "next_objective": "暴君",
  "objective_eta_sec": 24,
  "lane_state": "mid_pushed_ally",
  "heroes_closing_distance": true,
  "confidence": 0.91
}
```

最低限度应能识别：游戏时间、双方可见人数、关键英雄消失、血量风险、兵线方向、暴君/主宰刷新时间、多人接近和交战信号。

### 3.3 “什么时候打团”的决策

系统输出四类动作之一：

| 决策 | 触发条件 | 示例建议 |
| :--- | :--- | :--- |
| **接团** | 己方人数不劣、核心技能可用、有线权或地形优势、目标价值足够高 | “中线已推，张飞有大，等镜露头后接暴君团。” |
| **拉扯** | 人数接近，但血量、技能或位置不理想 | “先逼对方交控制，别一次性全开，等下一轮技能。” |
| **撤退** | 敌方人数领先、己方核心缺席/低血量、敌方已进入有效开团距离 | “关羽和海月消失，收线到塔前，暂不接河道架。” |
| **换资源** | 无法安全到场，但另一侧有可兑现的塔、兵线或野区资源 | “暴君接不了，四人推中一塔，打野反下半区。” |

判断至少综合人数、血量、关键技能、线权、位置和目标价值，不能只根据“双方靠近”就判定应该打团。

### 3.4 DeepSeek 接口调用

DeepSeek 接收三类信息：当前局面状态 JSON、知识库召回的战术片段、最近一次建议及其是否过期。要求只返回结构化结果：

```json
{
  "decision": "engage|kite|retreat|trade",
  "urgency": "now|soon|watch",
  "message": "暴君 24 秒刷新：先推中线，张飞保留大招，镜露头后再接团。",
  "reason_codes": ["ally_number_advantage", "objective_soon", "mid_priority"],
  "confidence": 0.84,
  "expires_in_sec": 12
}
```

DeepSeek 不建议直接接收连续视频帧。默认由视觉模型完成画面识别，再将状态 JSON 发送给 DeepSeek，可降低延迟、调用成本和幻觉风险。若后续验证 DeepSeek 的视觉接口满足延迟和稳定性要求，可作为备用识别通道。

### 3.5 判断用户是否执行建议

系统不能确认玩家的主观意图，只能根据画面判断可观察行为：

- 建议“推线后接团”：检测中线推进、队伍移动方向和目标刷新前是否靠近河道；
- 建议“撤退”：检测是否远离敌方、回到塔区或停止追击；
- 建议“击杀后转塔/资源”：检测击杀后 10 秒内的移动目标和攻击对象；
- 检测多人靠近、技能特效、伤害交换或英雄死亡，标记为“发生交战”；
- 结合交战前后的人数、经济、目标和防御塔状态，生成执行结果。

记录格式：

```json
{
  "advice_id": "adv_0021",
  "decision": "retreat",
  "issued_at": 285,
  "expires_at": 297,
  "observed_action": "engage",
  "action_confidence": 0.78,
  "outcome": "ally_two_deaths_no_objective",
  "review": "中线未推完便在河道接团，敌方先到场。"
}
```

这类记录用于赛后复盘和模型评估，不用于自动操作，也不应把一次团战结果简单等同于建议正确或错误。

### 3.6 频率、延迟和降级策略

- 普通局面以 1~2 FPS 低分辨率识别；出现事件候选时临时提高到 3~5 FPS。
- 连续 1~2 秒确认事件后再调用 DeepSeek，目标是 1~2 秒内返回建议。
- 建议有效期 8~15 秒；局面变化或关键英雄现身后立即刷新。
- 视觉置信度低于 0.8，或连续两帧状态冲突时，只显示“局面识别中”或模板化保守提醒。
- DeepSeek 或网络不可用时，回退到规则模板，例如“人数不足，先清线撤退”。
- HUD 只展示一条主建议和一个备用动作，避免局中信息过载。

### 3.7 排期调整

| 周期 | 增补任务 | 验收标准 |
| :--- | :--- | :--- |
| 第 1 周周三 | 视觉模型输出局面状态 JSON；增加 DeepSeek 接口适配层 | 给定测试截图，能稳定返回结构化状态和教练建议 |
| 第 2 周周二 | 事件规则引擎：目标刷新、人数差、关键英雄消失、多人接近 | 相同事件去重；单次事件只触发一条建议 |
| 第 2 周周四 | 接团/拉扯/撤退/换资源决策和 HUD 有效期 | 建议在 2 秒内显示，过期后自动消失或刷新 |
| 第 3 周周二 | 建议执行检测：推线、撤退、交战、击杀后转资源 | 能记录 advice、observed_action、outcome 三类结果 |
| 第 3 周周四 | 赛后复盘加入“建议是否执行、执行后结果如何” | 战报中出现一条具体行为复盘和下一局训练目标 |

| 阶段 | 玩家 / 游戏动作 | 大屏呈现 | 底层逻辑与知识库调用 |

| **3. 阵容加载** | 双方 10 人全部锁定，进入 VS 加载界面 | 大屏侧边切出“前中期战术要点”：对线优劣势评级、前期野区防守防抓策略 | 识别双边阵容 → **知识库匹配对位优劣** → 生成 80 字对局战术指南。 |

| **5. 终局复盘** | 水晶爆炸，出现 VICTORY/DEFEAT 结算大表 | 大屏淡出游戏画面，居中展示带 AI 评语的对局战报与二维码 | 触发 Qwen-VL 视觉分析战绩大图，提炼胜负关键手与趣味总结。 |
| **6. 扫码离场** | 玩家掏出手机扫描大屏二维码 | 手机端瞬间加载带 AI 专属评语的战报海报，支持一键保存发圈 | 完成社交与体验闭环。 |

### 无摄像头演示顺序

1. 运行项目的 `start.ps1`，打开 `http://127.0.0.1:8765`。
2. 点击「载入示例阵容」→「生成战术方案」，观察右侧 HUD 和加载计划。
