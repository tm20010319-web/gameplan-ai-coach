## 连续采集与视频实时播放（2026-09-16）

独立监控的屏幕采集与模型识别已分开：采集目标间隔为 100 毫秒，实际速度取决于截图接口和设备，只保留最新一帧。默认识别后不额外等待，模型和建议生成期间仍更新预览；同一时间只发送一个识别请求，不积压旧截图。首次打开新版会将旧的等待间隔切换为连续识别，之后可自行修改。

上传的视频按正常速度播放，模型完成一帧后读取当前播放位置，取消原来的每 3 秒跳转取帧。暂停后从暂停位置继续。实时播放会跳过模型忙碌期间的画面，因此不等于逐帧识别，也不能保证捕获瞬间施放。Ollama 推理仍受模型与硬件速度限制。

已通过 28 项前端模拟测试及 JavaScript 语法检查，包括慢推理期间持续采集、只处理最新帧、暂停恢复、切换视频和停止后丢弃旧结果；实际设备帧率和真实对局识别速度尚未实测。

## 独立桌面监控

2026-09-16：整屏 / 视频监控中的“敌方技能介绍与冷却”已接入本地技能资料。识别到敌方英雄后直接展示大招效果和各技能等级的基础冷却，展开可查看其余技能与被动；无需等待施放。资料覆盖 130 位英雄，缺失条目明确显示待补充。施放记录独立显示估算剩余时间，同一技能保留最近一次施放；特殊冷却机制保持未知，暂停后冻结显示。已通过 34 项监控前端测试；基础值估算仍未计冷却缩减、刷新或回放时间校准，尚不代表真实对局自动施放识别已验收。

桌面双击「实时桌面监控」快捷方式，即可打开独立窗口，不需要打开原工作台。也可在项目目录运行：

```powershell

```

默认地址为 [独立监控页面](http://127.0.0.1:8767/monitor)。启动器会在需要时隐藏启动 `monitor_app:app`，再次运行会复用已有服务；使用 Edge / Chrome 的独立应用窗口，未找到时使用默认浏览器。原工作台右上角也提供「独立桌面监控」入口，点击后暂停该工作台的采样。2026-09-10 最后一次原服务重启被自动审批拦截，最新版本已在 8767 运行，启动器默认端口同步更新；原 8766 服务仍在。

- 默认是固定画面分析：点击「框选固定画面」，拖出游戏图片范围，选择「使用此区域并开始」。约每秒检查一次，连续两次稳定采样后分析；换图片立即撤下旧建议。模型处理时采样继续，只处理最新图，不积压旧截图。
- 同一显示器会记住区域，之后打开窗口可自动监控；图片窗口移动后需重新框选。没有选过区域时先等待框选，不把整屏直接发送给外部模型。仅查看界面可访问 `/monitor?monitor=off`。
- 可反复「选择图片试分析」，或点击「使用这次截图」。选择第一组/第二组及重点英雄会重新分析；阵容有误可展开核对并修正，换图自动清除旧修正。
- 图片清晰度不足或两次识别分歧较大时，只展示 DeepSeek 的通用打法。具体英雄方案须先核对，不能将候选识别当成已确认事实。暂停冻结预览并撤下建议；停止或关闭窗口停止本页采样。
- 保留旧整屏 Qwen 监控入口 `/monitor?mode=screen`，其原观察设置和文本分析流程仍可使用。
- 独立后台不加载训练数据库、复盘或战报模块，复用本机 Ollama、项目 `.env` 与共享识别逻辑。关闭窗口后服务保持待用，Ollama 不会被终止。
- 只启动后台：`./start-monitor.ps1 -NoWindow`；修改端口：`./start-monitor.ps1 -Port 8768`。端口属于其他服务时会报错，不会终止其他程序。
- 后台日志位于 `work/monitor-logs/`。这仍是本地项目启动方式，并非单个可搬走的 EXE；移动项目后需更新快捷方式。

视觉接口配置 `DEEPSEEK_VISION_MODEL`，现已按用户要求切换到 `deepseek-v4-pro`。2026-09-10 核验模型清单并完成图片请求，实际响应模型为 `deepseek-v4-pro`；此前视觉别名返回 `deepseek-flash` 的配置已替换。配置按请求读取，无需重启，旧图片点击「重新检查并分析当前图」会按新模型重新分析。视觉请求超时 65 秒。接口故障会明确提示；Qwen 不可用时允许 DeepSeek 独立分析并注明来源。V4 测试仍出现英雄误认，模型名称核验不等于识别准确率验收，保留待核对与人工修正。

## 自动观察与外部模型建议

打开本机工作台后，默认自动监控所选显示器；可取消「进入工作台后自动监控所选屏幕」，或随时暂停/停止。示例链接只对样本调用一次 Qwen3-VL，不采集整个桌面；大屏展示页面也不自动采集。仅查看页面可加 `monitor=off`。

Qwen3-VL 提取游戏阶段、阵容和可靠的可见状态，DeepSeek V4 分析双方的风险、优势机会与配合方式，并在右侧「AI 对局建议」显示一段行动建议。选择方案方或英雄后会更新分析方向；不知道用户阵营时不假定己方。

**动态跟随英雄：** 选人、加载和局中均可随每次识别自动替换阵容。默认「英雄优先」模式减少输出字段；明确读到操控英雄后自动切换个人任务与建议，英雄变化时撤下旧建议。低把握、看不清或不在可见阵容的操控英雄保持待确认，不限于网上样本中的十位英雄，也不承诺所有英雄、皮肤都已准确识别。需要血量和自身技能数字时选择「完整状态」。

页面选择查看英雄后转为手动视角，勾选「自动跟随画面中确认的操控英雄」可恢复。手动修正阵容后不会被新帧覆盖，点击「恢复自动识别阵容」可重新跟随。网上截图仍是静态来源；点击「开始屏幕监控」会退出样本模式，刷新页面也会保持实际屏幕入口。

本机文本分析配置 `DEEPSEEK_MODEL` 同步设为 `deepseek-v4-pro`。密钥仅保存在本机 `.env`，不返回浏览器或写入分析结果。配置项为 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`；修改后点击重试即可读取最新配置，无需重启。此工作台/旧整屏文本链路只外发白名单游戏字段和机制资料；新的固定图片多模态链路按用户授权外发选中图片，规则见上文。

相同信息复用分析，单局外部请求至少间隔 20 秒；阵容建议最长缓存 120 秒。过期画面只允许生成标明范围的阵容建议，当前状态建议必须在采样 12 秒内仍有效。缺少密钥、超时或结果校验失败时明确显示「本地备用建议」，不冒充外部模型结果。

## 监控整块屏幕

通过本机地址打开工作台，自动检查本地 Ollama 并开始整屏观察；也可选择显示器后点击「开始屏幕监控」。默认每次识别完成后立即采集下一帧，也可选择等待 1 / 2 / 5 秒。每页最多一帧在识别，不累计旧截图；外部分析异步进行，不阻塞下一帧。可暂停观察或停止采集；关闭页面停止前端循环，浏览器后台节流可能降低采样频率。

本机截图最长缩放到 1280×720，自动观察不落盘。英雄优先模式将横屏按有少量重叠的上下区域读取，提升小字可读性；输出名称受本地英雄目录约束，低把握结果留空。接口仅允许本机同源访问。

本机 `qwen3-vl:8b` 的 GPU 加速已恢复，Ollama 显示 `100% GPU`。英雄优先样本从 CPU 约 32 秒降至 GPU 热启动约 2.35～3.16 秒；首次加载及初始化曾耗时约 33 秒。两张近似样本一次误认 1 位英雄，另一次 10 位均与人工核对一致；这不代表全英雄准确率，也未完成真实选人连续换英雄验收。2026-09-09 曾因 Windows 输入桌面访问错误 5 暂停，2026-09-10 独立模块复测已恢复连续采集；仍需保持电脑解锁及远程连接，不宣称能捕捉瞬时施放事件。

加速修复：Windows 旧版 `MSVCP140.dll` 14.36 导致 Ollama GPU 探测崩溃，现将 Ollama 自带且签名有效的 14.44 C++ 运行库放到其 `lib/ollama` 程序目录，并重启 Ollama，未修改系统运行库。新增文件记录见 `work/ollama-local-runtime-fix.json`；Ollama 升级后需重新核对兼容性。游戏和模型同机时的帧率影响仍待实测。

## 启动

## 5 分钟演示

1. **赛前战术**：点「载入示例阵容」后生成方案；也可点 10 个位置逐个选择。每队最多 5 人，不允许重复。
2. **同步大屏**：打开右上角「打开同步大屏」，同一对局实时推送；刷新后恢复已保存的阵容与未过期建议。大屏只同步战术，素材画面需在大屏本机打开 / 共享。
3. **局中观察**：点「目标将刷新」「人数劣势」「关键英雄消失」「安全换资源」等示例，确认后评估。示例有明确标记，不是真实对局观察。未知人数 / 技能不能触发强开建议。
4. **执行记录**：选择建议，输入可观察动作、局内秒数、置信度和结果。建议在 285 秒发出则 285~297 秒是观察有效窗口；超时观察标为不确定，而非没有执行。
5. **赛后复盘**：手填胜负、英雄、KDA 及已知资源数据，生成 PNG、二维码与 H5。空值不补成 0，不编造 MVP、伤害和胜负原因。
6. **英雄知识库**：支持英雄 / 机制 / 分路检索，以及 60 个完整条目浏览。
7. **技能计时预研（未完成新增需求验收）**：现有人工登记入口可用于检查记录、倒计时和提示。目标流程是敌方施放后自动识别并计时，具体见下方需求说明。

## 敌方技能释放记录与倒计时

本项目前为需求定义与预研阶段。完整业务规则、示例和验收标准统一维护在 [需求规格](docs/requirements/敌方技能释放记录与冷却提醒_需求规格.md)，以下均为目标行为：

- **自动记录**：连续观察敌方施放，自动确定英雄、技能和释放时间；按采集时刻计算，不把推理完成时刻当作释放时刻。
- **自动计时**：结合经过核验的版本、技能等级、冷却影响和冷却起点计算。条件不全时显示范围或未知，不能直接套用一个官网基础值。
- **到期提醒**：常驻多技能倒计时，最后 5 秒轻量提示，到点提醒「预计可用」；只有直接证据才标为「已确认可用」。
- **人工兜底**：支持漏识别补录、英雄 / 技能 / 时间 / 冷却纠错及撤销。只知道剩余秒数时不编造释放时间。
- **状态维护**：按对局保存并同步大屏，处理去重、再次施放、刷新恢复、暂停、回放跳转和对局结束。
- **完成标准**：在明确支持的英雄 / 技能清单内，以真实游戏画面验证自动识别闭环。手动计时可用不等于本需求已完成。

现有预研仍以手动登记、现实时间推进为主，尚未满足自动识别及本文要求的完整时间校准和纠错流程。首批支持清单、目标硬件和验收指标需在需求评审时确定。

## 画面来源（均不需要摄像头）

- 上传 PNG/JPEG/WebP 截图（8MB 内），或播放本地浏览器支持的录屏视频，暂停后分析当前帧。
- 本机打开 scrcpy / OBS 预览，再点「共享投屏窗口」选择该窗口；不采集麦克风和摄像头。
- scrcpy 需安卓手机、USB 数据线与手机端 USB 调试确认；这部分没有现场设备，未测 50ms 时延。
- 图像可按归一化 x/y/宽/高裁切。ROI API 实际裁切，不仅改变显示；上传原文件与用于模型的裁切 JPEG 均留存。
- 支持人工触发截帧，也可手动开启连续观察，读取阶段、操控英雄、血量及自身可见技能倒计时；敌方技能释放仍由人工确认登记。视觉草稿必须人工核对后提交。
- 浏览器屏幕共享需要 localhost 或 HTTPS，局域网 HTTP 通常不支持共享；手机只看战报不受影响。

## 手机分享与数据安全

- 默认按当前站点 / 网卡生成分享地址。当前电脑有 VPN 和虚拟网卡，已在本地 `.env` 配置 WLAN 地址 `http://192.168.0.46:8765`。换网络或端口时修改 `PUBLIC_BASE_URL=http://电脑局域网IP:端口`，重启后重新生成战报。
- 扫码目标是本机 H5，不上传第三方平台；无需外部 CDN、在线二维码或外部字体。
- 手机与电脑需同网，排查访客 Wi-Fi 隔离、防火墙和路由。生成二维码不等于已验证手机能够访问。
- 对局和战报使用随机 ID；这是**可信局域网演示版，无账户鉴权**。知道对局链接的人可查看 / 更新此对局；持有战报链接的人可看该海报。
- 不要端口转发或直接暴露公网。正式部署需加认证、访问控制、TLS、上传限速、备份与保留策略。
- `data/coach.sqlite3` 保存对局状态、建议、人工观察与审计；`data/frames/` 保存服务端收到的原始字节 `.bin` 和处理图 `.jpg`；`data/reports/` 保存海报。网页发送前会把当前帧缩放至最多 1920×1080，因此这里不是本地原视频或原图的备份。
- 服务不会自动清理历史。截图可能包含玩家昵称等个人信息，分享前核对，部署前制定保留策略。

## API 摘要

交互文档：`/docs`。所有 POST JSON 均有输入验证。

下表技能计时接口是此前预研代码的接口，尚不代表自动识别需求已验收；后续接口设计以需求评审结果为准。

| 接口 | 用途 |
| --- | --- |
| GET /api/health, /api/config | 健康、配置状态（不包含密钥） |
| GET /api/heroes, /api/knowledge/search?q=关羽 | 英雄与关键词检索 |
| POST /api/matches | 创建独立对局 |
| GET /api/matches/{match_id} | 阵容、有效建议、最近 100 条记录 |
| GET /api/matches/{match_id}/skill-timers | 技能计时、最近 100 条历史、服务端时间和修订号 |
| POST /api/matches/{match_id}/skill-timers | side、hero、slot、mode、seconds、可选 elapsed_s / game_time_s |
| POST /api/matches/{match_id}/skill-timers/clear | 清空当前计时，保留历史 |
| POST /api/matches/{match_id}/skill-timers/{timer_id}/cancel | 移除单个计时，保留历史 |
| POST /api/bp/advice | enemy_heroes、ally_heroes、match_id |
| POST /api/in_game/advice | state_json、match_id、source |
| POST /api/matches/{match_id}/records/{advice_id}/observation | 动作、局内秒数、置信度、结果 |
| POST /api/vision/bp、analyze、result、crop | image_base64、可选 model / roi |
| POST /api/post_game/review | result 结算字段、match_id |
| GET /api/reports/{id}、/{id}/poster.png、/{id}/qr.png | 战报数据 / 图片 |
| GET /r/{id} | 手机战报 H5 |
| WS /ws/{match_id} | 同对局快照、BP、建议、观察、战报、skill_timers 事件 |

局中状态采用嵌套 `heroes / map / combat_signal`，完整字段见 `gameplan/core/models.py` 和 Swagger。
`heroes.confidence` 与 `map.confidence` 任一不足 0.8 均保守处理；人数、技能、血线空值不视为确认。
`source=vision` 需同一候选持续至少 1 秒，相邻采样间隔不超过 3.5 秒；相反建议在 2 秒内跳变时不触发。人工核对与示例输入无此等待。
相同有效事件去重，建议 12 秒过期；新局面清除旧建议，过期后可重新分析。单机请使用一个 uvicorn worker，多进程需外部广播和共享锁。
